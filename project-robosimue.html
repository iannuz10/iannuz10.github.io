RoboSimUE: High-Fidelity Hybrid Robotics Simulation Infrastructure

A decoupled simulation environment bridging the photorealistic rendering of Unreal Engine 5 with the scientific physics of MuJoCo, achieving sub-3ms latency via Zenoh.

At a Glance

  • Situation: Traditional robotics simulators often force a strict trade-off: prioritize visual fidelity or prioritize physics performance. Generating high-quality synthetic data requires both, but rendering engines drag down physics calculations when coupled together.
  • Task: To design and engineer a decoupled "Digital Twin" infrastructure that physically separates Unreal Engine 5's visual rendering (Host) from a Linux-based MuJoCo physics backend (Guest), while maintaining seamless real-time synchronization.
  • Action: I built a custom, modular network bridge utilizing Zenoh as a high-performance DDS alternative. The architecture required developing a C++ multithreaded foundation in UE5 to bypass the Game Thread, alongside a highly optimized, vectorized Python backend running inside a Docker container.
  • Result: Achieved a highly stable 60Hz bidirectional physics-to-visual loop with a Round-Trip Time (RTT) averaging ~2ms. The system successfully generates dynamic worlds, parses complex JSON state payloads instantly, and supports native MJCF robotic models.

Technical Deep Dive

Host-Guest Topology

The infrastructure operates on a strictly decoupled architecture to maximize computational efficiency across environments:

  • The Host (Unreal Engine 5): Acts as the "Body" and "Eyes." It runs on a Windows/Mac host machine, dedicating all resources to high-fidelity rendering (Nanite/Lumen), kinematic visualization, and dynamic world serialization.
  • The Guest (Dockerized Linux): Acts as the "Brain." It runs an isolated container with Python and MuJoCo. The backend dynamically constructs the physical worldbody in memory based on the initial UE5 payload and calculates continuous physics steps.

High-Performance Networking (Zenoh & C++)

Achieving real-time synchronization required eliminating artificial latency introduced by standard game engine rendering loops.

  • Bypassing the Game Thread: Standard UE5 Blueprints lock network execution to the frame rate (~16ms). I engineered an FRunnable C++ background thread to catch incoming Zenoh packets via an "Envelope Split" architecture. This allows the system to instantly publish network ACKs in microseconds before handing structured data to the Game Thread.
  • O(1) Memory Caching: Ripped out expensive GetAllActorsWithTag loop operations by implementing a Just-In-Time (JIT) TWeakObjectPtr mapping system, guaranteeing constant-time memory lookups during the 60Hz visual update cycle.

Vectorized Physics Backend (Python)

The Guest environment was rigorously profiled and optimized to eliminate Python bottlenecks and OS scheduling jitter.

  • NumPy Vectorization: Replaced manual iteration loops with C-compiled NumPy array operations for coordinate conversions (Right-Hand to Left-Hand) and quaternion inversions, processing hundreds of dynamic props simultaneously.
  • Zero-Copy Serialization: Replaced standard JSON libraries with the Rust-based orjson library. By directly serializing raw NumPy arrays, the system completely eliminated 100ms+ Python Garbage Collection (GC) spikes, locking the payload processing time to a fraction of a millisecond.
  • Dynamic Timestep Alignment: Programmed a dynamic substep calculator that automatically aligns MuJoCo's internal clock with the target host FPS, ensuring the physics simulation never drifts from real-time execution.

Mesh Pipeline & Asset Ingestion

To ensure 1-to-1 parity between the scientific models and the visual engine, a custom asset pipeline was formalized for importing native .mjcf models:

  • Automated Conversion: Created a Python visual-URDF generator to extract standard MuJoCo XMLs, correcting internal mesh offsets automatically.
  • Blender LinkForge Pipeline: Utilized Blender plugins to ingest the URDF and export animation-free, cleanly axised glTF 2.0 files into Unreal Engine 5.
  • Blueprint Harvesting: Converted the raw hierarchical meshes into dynamic UE5 Actors capable of instantly attaching to the C++ simulation receptors.
